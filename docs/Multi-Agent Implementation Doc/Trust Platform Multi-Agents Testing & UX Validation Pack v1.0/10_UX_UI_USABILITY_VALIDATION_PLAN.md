# 10 — UX/UI & Usability Validation Plan

## UX principles
The product must feel trustworthy, simple and transparent. Optimize for task completion, not feature exposure. Critical screens must answer: what is happening, what do I need to do, what will it cost, what happens next, and can I safely undo/cancel?

## Primary usability tasks
Member: create Request; understand proposals; compare/choose; understand total and custody; approve/reject Change Order; follow Partner ETA/status; review evidence and Service Summary; confirm completion; open dispute; rate Partner.
Partner: discover/receive opportunity; submit Proposal; understand fee/net economics; navigate to job; Check-in/Pause/Resume/Check-out; attach evidence; submit Change Order; understand payment/release status; rate Member.

## Acceptance targets
No critical task dead-end; irreversible action requires clear confirmation/context; monetary values and consequences are unambiguous; errors explain recovery; loading/empty/offline states are intentional; destructive actions are visually/semantically distinct; back navigation does not duplicate transactions. Capture task success, error count, time-on-task, abandonment point and qualitative friction. Any severe comprehension failure in payment/custody/release/dispute is release-blocking.
